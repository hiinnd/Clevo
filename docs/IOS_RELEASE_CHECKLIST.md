# CLEVO iOS release checklist

Reviewed 2026-11-22. This workspace runs Windows and has no Xcode/macOS or Apple signing environment. **No IPA, simulator/device test, signing, APNs delivery or TestFlight upload was performed.** Existing bundle ID `com.clevo.clevo` and minimum iOS 15 are repository configuration, not proof of ownership or eligibility.

- [ ] Approve Apple developer organization, legal/support/privacy identities, final bundle ID and team, capabilities, distribution profiles and recovery custody. Use ONE CLEVO target/role app. Do not put .p8/.p12/provisioning profiles or Secrets.xcconfig in Git.
- [ ] Use a compatible Mac with current supported Xcode. App Store Connect uploads require Xcode 26+ and iOS 26+ SDK since 2026-04-28; minimum target iOS13+ since 2026-09-09. Existing iOS15 target is compatible in principle; dependencies/native build are untested. Complete updated age-rating questions. [Apple requirements](https://developer.apple.com/news/upcoming-requirements/), [Xcode compatibility](https://developer.apple.com/xcode/system-requirements).
- [ ] Run `flutter pub get`, `pod install`, analyze/tests and native build with separate approved staging configuration. Resolve CocoaPods/SDK advisories and inspect transitive privacy manifests. Use native bundle/team overrides in approved private build settings, not server credentials in source. Keep Android/iOS public API config and Firebase projects aligned with their environments.
- [ ] Install real GoogleService-Info.plist through private build configuration; register bundle and APNs credential in the approved Firebase project. Enable Push Notifications capability with correct development/production APS environment only after valid provisioning. Existing example xcconfig/entitlement is preparation, not successful APNs setup.
- [ ] Restrict iOS Maps key to the approved bundle ID; validate foreground location usage explanations in Arabic/English, notification prompt, photo selection purpose and secure storage. Review every Info.plist permission from the merged artifact; do not request Always/background location. Current tracking works only while authorized active job and app usage permit it; background tracking is not approved.
- [ ] Produce an actual data inventory and inspect plugin/SDK privacy manifests, required-reason API usage, tracking declarations and App Store privacy labels. No blank/no-data PrivacyInfo.xcprivacy was added: that would misrepresent actual collection. Account/contact, financial metadata, uploaded verification, precise job GPS and device push tokens need accurate disclosure. [App privacy details](https://developer.apple.com/app-store/app-privacy-details/).
- [ ] Test account creation/verification/reset, all roles, in-app deletion confirmation/completion, privacy/terms/support links and legally reviewed retention. Account disable alone is insufficient. [Apple account deletion](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion).
- [ ] Review payment treatment against actual products: car washing/physical delivery normally falls under external physical-service payments in 3.1.3(e); separately assess any digital-only subscription benefits. This is not merchant approval or a blanket store exemption. [Review guidelines](https://developer.apple.com/app-store/review/guidelines/).
- [ ] On Mac run simulator widget/native integration and real iPhone tests: notifications/deep links, APNs tokens, authorized GPS/denials/staleness, payment browser return, network loss, secure storage/revocation, dark/light RTL/LTR, large text and VoiceOver. Inspect archive entitlements, signing, no development endpoints/secrets and expected ATS restrictions.
- [ ] Create archive/IPA using `flutter build ipa --release --dart-define-from-file=<public-config.json>` only after signing/configuration approval. Preserve dSYM and hashes privately; verify App Store Connect validation and encryption/export compliance from the actual SDK functionality, not an assumed exemption.
- [ ] After explicit publishing approval, upload approved internal TestFlight build, complete beta review where applicable, provide secure reviewer accounts with tested server-side roles, screenshots/descriptions and support URLs. No TestFlight availability is claimed by preparing these instructions.
